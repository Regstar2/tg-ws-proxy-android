# CF Proxy через WebSocket на порту 80

Режим из форка malordin добавлен как галка **CF Proxy без TLS** на экране **Настройки → Cloudflare → Управление доменами**. В исходном эксперименте галка была выключена по умолчанию. Начиная с кандидата 1.11.10, при отсутствии сохранённого значения она включена. Явно сохранённое false не перезаписывается; менять режим можно только при остановленном сервисе. При включении MTProto и SOCKS5 используют `ws://kwsN.<домен>:80/apiws` в рамках CF Proxy. Значение `Host` выбирает дата-центр. Порядок маршрутов задаёт прежняя сетевая политика. [Исходное изменение malordin](https://github.com/malordin/tg-ws-proxy-android/commit/2e4b7df86ec0c6612b095d8afffda61e384418a5)

У соединения с Cloudflare на порту 80 нет TLS и аутентификации сервера. При выключенной галке используется WSS с проверкой сертификата и имени. В 1.11.10 порт 80 используется по умолчанию при отсутствующем значении. Для проверяемого WSS/443 выключите «CF Proxy без TLS». Это отдельный эксперимент в рамках [issue #158](https://github.com/Regstar2/tg-ws-proxy-android/issues/158).

## Проверка на Xiaomi

19 ноября 2026 года проверили Xiaomi 2109119DG с Android 14. В обеих сетях активен только CF Proxy. После установки первоначальной подписанной debug-сборки галка была снята. Её включили через экран настроек и запустили прокси заново. SHA-256 APK `9D50736AA7419B61094CC59AA4B162CB396DCCCF2E79DCAB3E1DB091D70C8A3B`. Этот APK также содержал эксперимент HTTP/3. Все пробы ниже выполнялись через порт 80.

| Сеть | DC2, DC4, DC2 media, DC4 media | Время обмена `req_pq_multi → resPQ` |
| --- | ---: | ---: |
| Wi-Fi | 12 из 12 | 191–1440 мс |
| Мобильная | 12 из 12 | 336–437 мс |

В каждой группе было по три запроса с отдельным nonce. Журнал подтвердил `transport=ws port=80`, путь `/apiws` и `actual_backend=cf_proxy_ws`. Сборка Android, линтер, модульные тесты Android и `go test -race -count=1 ./...` прошли. Обработчик WebSocket проверяет `Sec-WebSocket-Accept`, `Upgrade` и `Connection` перед отправкой MTProto.

В Telegram News по Wi-Fi ролик 3,0 МБ загрузился к снимку на 3-й секунде. На мобильной сети другой ролик показывал 3,1 из 4,2 МБ на 3-й секунде, а к снимку на 8-й секунде значок загрузки исчез. Эти прогоны подтверждают завершение загрузок в двух сетях. Для сравнения скорости с HTTP/3 нужны одинаковые файлы и контроль кэша. [Ролик для Wi-Fi](https://t.me/telegram/429) · [Ролик для мобильной сети](https://t.me/telegram/430)

## Повторный прогон отдельной ветки порта 80

Подписанный APK из ветки `codex/158-cf-ws80` с SHA-256 `B8AA80FBFD8FBD15F4B596D5108569E11252B16CA2F5FBD629C7BEF64B0CBDD2` проверили на том же Xiaomi. Через порт 80 получены 12 из 12 корректных `resPQ` по Wi-Fi и 7 из 12 на мобильной сети. Остальные пять мобильных проб достигли 8-секундного дедлайна клиента. На каждой из четырёх групп DC2, DC4, DC2 media и DC4 media был хотя бы один корректный ответ в обеих сетях. Go-тесты с `-race`, тесты Android, lint и `assembleDebug` прошли на отдельной ветке.

Режим оставлен включённым на Xiaomi. Физические прогоны SOCKS5 и других маршрутов в этой итерации не проводились.

Журналы и снимки первоначальной сборки лежат в локальном каталоге `artifacts/issue158/20261119-ws80/`, повторного прогона отдельной ветки — в `artifacts/issue158/ws80-publish/`.

## Регрессионная проверка значения по умолчанию 1.11.10

- [ ] При отсутствии `cfproxy_no_tls` переключатель и runtime выбирают WS/80.
- [ ] При сохранённом `cfproxy_no_tls=false` переключатель и runtime выбирают WSS/443, в том числе после restart и запуска из Quick Settings.
- [ ] При сохранённом `cfproxy_no_tls=true` WS/80 не сбрасывается после restart.
- [ ] Изменить настройку можно только при остановленном прокси; route order не изменяется.
- [ ] RU/EN текст сообщает, что WS/80 не шифрует трафик и не подтверждает подлинность upstream.
- [ ] Реальное device-тестирование этого default-on изменения ещё не проводилось.
