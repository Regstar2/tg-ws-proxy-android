# TgWsProxy Android v1.11.8 — in-app updates and reliability fixes

[Русский](v1.11.8.md) · **English**

## About this release

v1.11.8 is a **planned compatible patch**, not a published release. It collects previously merged in-app APK update functionality, Fake TLS ingress hardening, Quick Settings consistency, and port-in-use feedback. No new outbound transport is introduced.

Metadata: `versionName 1.11.8`, `versionCode 64`, Android 8.0+ (`minSdk 26`), `arm64-v8a` only, package `io.github.regstar2.tgwsproxy`. No public release tag or GitHub assets exist yet. A locally signed candidate APK and checksum were built and verified on November 12, 2026; preserving data when upgrading from v1.11.7 has not yet been verified.

## Highlights

- Download and verify the official APK within the application before handing it to Android's package installer.
- Invalid inbound Fake TLS handshakes no longer overwrite the confirmed outbound MTProto route status.
- The Quick Settings tile bases its appearance and tap action on a consistent frontend state.
- An open application displays a short message when a local proxy port is demonstrably in use.

## Changes

### Added

- **Updates:** progress, cancel, official ARM64 APK validation (SHA-256, signing certificate continuity, package name, version, minSdk and ABI) and user-approved Android installer handoff. An optional startup prompt and reminders are available; silent installation is not ([#139](https://github.com/Regstar2/tg-ws-proxy-android/issues/139), [PR #144](https://github.com/Regstar2/tg-ws-proxy-android/pull/144)).
- **Fake TLS diagnostics:** classify malformed input, record dedicated rejection counts and sample repetitive handshake-failure log lines without recording secrets ([#138](https://github.com/Regstar2/tg-ws-proxy-android/issues/138), [PR #145](https://github.com/Regstar2/tg-ws-proxy-android/pull/145)).

### Changed

- The startup update prompt initiates the verified download directly. If Android requires permission to install from this source, the user is taken to the relevant system settings; returning after denial does not reopen settings indefinitely.
- Automatic GitHub Releases checks cache results while manual checks request fresh data.

### Fixed

- **Fake TLS:** failed inbound attempts cannot overwrite the confirmed outbound route or its last error. Invalid-connection pressure is represented by counters without one full log entry for every rejection ([PR #145](https://github.com/Regstar2/tg-ws-proxy-android/pull/145)).
- **Quick Settings:** the tile uses one state decision for display and tap handling; transitions and inconsistent snapshots become temporarily unavailable instead of exposing a misleading active/stop choice ([#146](https://github.com/Regstar2/tg-ws-proxy-android/issues/146), [PR #147](https://github.com/Regstar2/tg-ws-proxy-android/pull/147)).
- **Port busy:** confirmed `PORT_BUSY` for MTProto or SOCKS5 triggers a concise localized notice in the open app, suggesting a port change without showing a port number. Other errors do not show this notice ([#148](https://github.com/Regstar2/tg-ws-proxy-android/issues/148), [PR #149](https://github.com/Regstar2/tg-ws-proxy-android/pull/149)).

## Installation and updating

When the release is published, use the official [GitHub Releases](https://github.com/Regstar2/tg-ws-proxy-android/releases). The planned files are `TgWsProxy-Android-v1.11.8-arm64-v8a.apk` and the companion `.apk.sha256`; neither has been published.

For v1.11.7 → v1.11.8, use an APK signed by the same key and install **without uninstalling** to preserve app configuration. Verify Wi-Fi/mobile routes, Worker settings, AWG/WARP profiles, and MTProto traffic afterward; the final release-to-release upgrade is **NOT RUN**. Builds before v1.11.6 used `com.amurcanov.tgwsproxy`, a different package ID, and cannot update this application in place. Two proxies cannot bind the same local port simultaneously.

The in-app update path requires reachable official GitHub/CDN assets and user-granted Android installation permission. Android asks the user to confirm installation. The fallback is the official release page, never an unverified APK. In-place downgrade to a lower versionCode has not been verified; back up important configuration before attempting any rollback.

## Known issues

- The original November 5 burst of 11,801 spontaneous loopback Fake TLS rejects was **not attributed**. The mitigation was tested under synthetic pressure; the original caller/root cause was not identified. Issue #138 was closed at the owner's request without further investigation.
- In-app updating lacks complete device evidence for all failure paths, permission denial, persistence of every setting and an upgrade between two release-built signed APKs; see [#139 acceptance](../testing/issue-139-in-app-update-acceptance.md).
- Flowseal Legacy WebSocket remains experimental. Only ARM64 is supported. Quick Settings visuals can vary with Android SystemUI.
