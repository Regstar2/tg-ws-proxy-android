# v1.11.6 — надёжность CF Proxy и отдельный Android-пакет

**Русский** · [English](v1.11.6_EN.md)

## О релизе

v1.11.6 — stable patch для TgWsProxy на Android 8.0+ и `arm64-v8a`. Версия исправляет поведение CF Proxy при истощении пула доменов и массовых переподключениях, отменяет устаревшие TLS-попытки после остановки или смены маршрута и устраняет конфликт идентификаторов Android-пакетов. Рабочие маршруты и ранее восстановленное соединение MTProto остаются частью версии; изменения не добавляют нового метода обхода сетевых ограничений.

Метаданные: `versionName 1.11.6`, `versionCode 62`. Название приложения `TgWsProxy` не меняется.

## Главное

- При исчерпании CF domain pool ограничены бесполезные исходящие соединения, причина отказа классифицируется явно.
- После stop/reconfigure старые CF DNS/TCP/TLS/WebSocket-подключения отменяются, а события относятся к своему поколению маршрута.
- Изменён `applicationId` на `io.github.regstar2.tgwsproxy`: новая сборка устанавливается независимо от оригинального приложения.

## Изменения

### Изменено

- **CF Proxy:** при отсутствии пригодных доменов возвращается быстрый `cfproxy_unavailable`; дублирующая диагностика и попытки reconnect ограничены. Cooldown остаётся независимым для DC, fallback подчиняется разрешённой политике ([#125](https://github.com/Regstar2/tg-ws-proxy-android/issues/125), [PR #129](https://github.com/Regstar2/tg-ws-proxy-android/pull/129)).
- **MTProto lifecycle:** незавершённые CF dial/handshake отменяются при stop и смене маршрута. Исходное поколение маршрута сохраняется в telemetry, так что поздние CF-события не выдают себя за новый AWG fallback ([#126](https://github.com/Regstar2/tg-ws-proxy-android/issues/126), [PR #130](https://github.com/Regstar2/tg-ws-proxy-android/pull/130)).

### Исправлено

- **Android package identity:** `com.amurcanov.tgwsproxy` заменён на `io.github.regstar2.tgwsproxy` только как `applicationId`, Kotlin namespace и имя приложения сохранены. Debug ADB-сценарии направлены на новый пакет ([PR #131](https://github.com/Regstar2/tg-ws-proxy-android/pull/131)).
- **Проверка APK:** CI проверяет package, launchable activity и `FileProvider`; релизный скрипт сверяет новый package и версию перед публикацией.

### Несовместимые изменения

- Новый Android `applicationId` означает **отдельную установку**, а не обновление предыдущего APK поверх него. Настройки, AWG/WARP-профили и другие данные не мигрируют автоматически.

## Установка и обновление

Загрузите подписанный `TgWsProxy-Android-v1.11.6-arm64-v8a.apk` на [странице релиза](https://github.com/Regstar2/tg-ws-proxy-android/releases/tag/v1.11.6). Необходимы Android 8.0+ и архитектура ARM64. Проверяйте SHA-256 скачанного файла.

Сборка с `io.github.regstar2.tgwsproxy` устанавливается отдельно от ранее выпущенного `com.amurcanov.tgwsproxy`. Перед удалением прежней установки сохраните необходимые настройки доступным способом; новая установка требует отдельной настройки прокси и AWG/WARP. Два запущенных экземпляра не могут слушать один порт (по умолчанию `127.0.0.1:1443`). Откат с переносом настроек между разными пакетами не предусмотрен.

Проверка обновлений открывает страницу GitHub Releases; автоматической установки APK нет.

## Проверено

- Исправления #125 и #126 интегрированы в `main` через PR #129 и #130 после CI и профильных регрессионных проверок.
- Для отдельного `applicationId` пройдены Windows CI, Android unit tests, сборка Debug APK и Worker transport regression. Итоговый commit проверяется при подготовке тега и повторно в release workflow.
- Подписанный Debug APK с новым идентификатором устанавливается и запускается. Подпись и метаданные итогового Release APK проверяются при выпуске; установка опубликованного APK проверяется отдельно.
- Дополнительные release gates перечислены в [чек-листе](RELEASE_CHECKLIST.md).

## Известные проблемы

- Отдельная проверка совместимости установки нового пакета ещё требуется перед завершением [#128](https://github.com/Regstar2/tg-ws-proxy-android/issues/128).
- APK выпускается только для `arm64-v8a`, без 32-битного ARM-варианта.
- Доступность Cloudflare Proxy и Worker зависит от сети. Flowseal Legacy WebSocket остаётся экспериментальным транспортом.
- Два локальных сервиса не могут слушать один и тот же порт одновременно.

## Артефакты

В GitHub Release публикуются:

- `TgWsProxy-Android-v1.11.6-arm64-v8a.apk` — подписанный Release APK.
- `TgWsProxy-Android-v1.11.6-arm64-v8a.apk.sha256` — контрольная сумма этого APK.

Фактические размер и SHA-256 определяются при сборке и публикуются с артефактами. Debug APK не является релизным артефактом.
