# v1.11.6 — CF Proxy reliability and distinct Android package

[Русский](v1.11.6.md) · **English**

## About this release

v1.11.6 is a stable patch for TgWsProxy on Android 8.0+ / `arm64-v8a`. It fixes CF Proxy behavior during domain pool exhaustion and reconnect spikes, cancels obsolete TLS attempts after stopping or changing a route, and prevents Android package ID collisions. Working routes and restored MTProto connectivity are retained; this release does not introduce a new network-circumvention method.

Metadata: `versionName 1.11.6`, `versionCode 62`. The visible app name remains `TgWsProxy`.

## Highlights

- Exhausted CF domain pools no longer initiate unnecessary outbound connections; failure reasons are explicitly classified.
- Stop/reconfigure cancels old CF DNS/TCP/TLS/WebSocket attempts and attributes events to the correct route generation.
- The Android `applicationId` is now `io.github.regstar2.tgwsproxy`, allowing installation separately from upstream.

## Changes

### Changed

- **CF Proxy:** no eligible domains results in a quick `cfproxy_unavailable` response, with bounded reconnects and repeated diagnostics. Per-DC cooldown and explicit fallback policies are preserved ([#125](https://github.com/Regstar2/tg-ws-proxy-android/issues/125), [PR #129](https://github.com/Regstar2/tg-ws-proxy-android/pull/129)).
- **MTProto lifecycle:** in-flight CF dial/handshake attempts are cancelled on stop or route changes. Telemetry retains the originating route generation so late CF results are not mistaken for a new AWG fallback ([#126](https://github.com/Regstar2/tg-ws-proxy-android/issues/126), [PR #130](https://github.com/Regstar2/tg-ws-proxy-android/pull/130)).

### Fixed

- **Android package identity:** only the `applicationId` changes from `com.amurcanov.tgwsproxy` to `io.github.regstar2.tgwsproxy`. Kotlin namespace and display name are unchanged; debug ADB scripts target the correct package ([PR #131](https://github.com/Regstar2/tg-ws-proxy-android/pull/131)).
- **APK validation:** CI checks the packaged ID, launcher activity and `FileProvider`; the release script checks the new package and version before publication.

### Breaking changes

- The new Android `applicationId` creates a **separate installation**, not an in-place upgrade of an earlier APK. Settings, AWG/WARP profiles and other data are not migrated automatically.

## Installation and updating

Download the signed `TgWsProxy-Android-v1.11.6-arm64-v8a.apk` from the [release page](https://github.com/Regstar2/tg-ws-proxy-android/releases/tag/v1.11.6). Android 8.0+ and ARM64 are required. Verify the downloaded file's SHA-256.

The `io.github.regstar2.tgwsproxy` package installs alongside the earlier `com.amurcanov.tgwsproxy`. Retain any necessary configuration before uninstalling the older application; the new installation requires independent proxy and AWG/WARP setup. Two running instances cannot bind the same port (default `127.0.0.1:1443`). Data-preserving rollback across package identities is not provided.

The built-in update check opens GitHub Releases; it does not install APK files.

## Verification

- #125 and #126 fixes were integrated into `main` through PR #129 and #130 following CI and relevant regression checks.
- Windows CI, Android unit tests, Debug APK build and Worker transport regression passed for the new application ID. The final commit is checked before tagging and again by the release workflow.
- A signed Debug APK with the new package ID installs and launches. The release workflow verifies the final APK signature and metadata; installation of the published APK is a separate acceptance check.
- Additional release gates are listed in the [checklist](RELEASE_CHECKLIST.md).

## Known issues

- Additional installation compatibility checks are required before resolving [#128](https://github.com/Regstar2/tg-ws-proxy-android/issues/128).
- Only `arm64-v8a` is distributed; there is no 32-bit ARM APK.
- Cloudflare Proxy and Worker availability depends on the network. Flowseal Legacy WebSocket remains experimental.
- Two local proxy services cannot listen on the same port simultaneously.
