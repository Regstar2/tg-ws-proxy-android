# TgWsProxy Android v1.11.9 — Cloudflare Proxy connection fix

[Русский](v1.11.9.md) · **English**

## About this release

v1.11.9 is a compatible patch release addressing TLS timeouts on the Cloudflare Proxy route. TLS ClientHello now uses the base domain for SNI while HTTP WebSocket Host retains the DC-specific upstream name. Other routes and existing user settings are unchanged.

Prepared metadata: `versionName 1.11.9`, `versionCode 65`, Android 8.0+ (`minSdk 26`), `arm64-v8a`, `io.github.regstar2.tgwsproxy`. The signed APK and final checksums must still be verified separately.

## Highlights

- Cloudflare Proxy uses separate TLS SNI and WebSocket Host values while preserving DC routing.
- MTProto, SOCKS5 and RouteProbe share this contract; Direct WS, Worker and fallback order are unchanged.
- Adapted from the [malordin fork](https://github.com/malordin/tg-ws-proxy-android), [commit a98fd27](https://github.com/malordin/tg-ws-proxy-android/commit/a98fd27c384452b8b0e78a4273abf005077aad6b).

## Changes

### Fixed

- Cloudflare Proxy: TLS SNI uses the base domain; HTTP WebSocket Host remains `kwsN.<base-domain>` with path `/apiws`. TCP destination, IP fallback and DC selection remain intact ([#156](https://github.com/Regstar2/tg-ws-proxy-android/issues/156), [PR #157](https://github.com/Regstar2/tg-ws-proxy-android/pull/157)).
- RouteProbe uses the same TLS SNI/HTTP Host pair, without treating HTTP 101 as proof of working MTProto.
- Added TLS/WebSocket regression tests and a debug-only automated `cf_proxy_ws` acceptance scenario.

## Installation and updating

After publication, download the APK and its matching `.sha256` from the [official v1.11.9 release](https://github.com/Regstar2/tg-ws-proxy-android/releases/tag/v1.11.9). Updating from v1.11.8 requires the same signing certificate. **Do not uninstall the existing app**; that can remove route settings, Worker pool configuration and AWG/WARP profiles.

The old `com.amurcanov.tgwsproxy` package cannot update `io.github.regstar2.tgwsproxy` in place. In-place downgrade to a lower `versionCode` has not been verified. The built-in updater hands verified APKs to Android's system installer for user confirmation.

## Known issues

- [#154](https://github.com/Regstar2/tg-ws-proxy-android/issues/154): operator-specific connectivity reports remain open pending tests on those networks.
- [#155](https://github.com/Regstar2/tg-ws-proxy-android/issues/155): a Realme/Android 16 user reported notification reconnect failing with a port-in-use error; not fixed in this release.
- [#158](https://github.com/Regstar2/tg-ws-proxy-android/issues/158): existing native WebSocket TLS uses `InsecureSkipVerify=true` and does not validate the upstream certificate chain or hostname. PR #157 did not change this. A separate security decision is needed before stable publication.
- TLS handshake success or HTTP 101 does not prove delivery of Telegram messages or media. See [#156 acceptance](../testing/issue-156-cfproxy-sni.md).
