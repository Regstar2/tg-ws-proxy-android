# TgWsProxy Android v1.11.9 — исправление соединений через Cloudflare Proxy

**Русский** · [English](v1.11.9_EN.md)

## О релизе

v1.11.9 — совместимый patch-релиз для устранения таймаутов соединения по маршруту Cloudflare Proxy. В TLS ClientHello используется базовый домен зоны, а HTTP WebSocket Host по-прежнему определяет Telegram DC. Прочие маршруты и пользовательские настройки не изменяются.

Подготовленные метаданные: `versionName 1.11.9`, `versionCode 65`, Android 8.0+ (`minSdk 26`), `arm64-v8a`, `io.github.regstar2.tgwsproxy`. Финальный подписанный APK и контрольные суммы ещё требуют отдельной проверки.

## Главное

- Cloudflare Proxy использует раздельные TLS SNI и WebSocket Host, сохраняя DC-specific маршрутизацию.
- Изменение применяется к MTProto, SOCKS5 и RouteProbe. Direct WS, Worker и порядок fallback не меняются.
- Исправление адаптировано из [форка malordin](https://github.com/malordin/tg-ws-proxy-android), [commit a98fd27](https://github.com/malordin/tg-ws-proxy-android/commit/a98fd27c384452b8b0e78a4273abf005077aad6b).

## Изменения

### Исправлено

- Cloudflare Proxy: TLS SNI использует базовый домен, HTTP WebSocket Host сохраняет `kwsN.<base-domain>`, а путь — `/apiws`. TCP destination, IP fallback и выбранный DC сохраняются ([#156](https://github.com/Regstar2/tg-ws-proxy-android/issues/156), [PR #157](https://github.com/Regstar2/tg-ws-proxy-android/pull/157)).
- Встроенная диагностика RouteProbe использует ту же пару TLS SNI/HTTP Host и не трактует HTTP 101 как доказательство работающего MTProto.
- Добавлены регрессионные тесты TLS/WebSocket и debug-only сценарий автоматизированной проверки `cf_proxy_ws`.

## Установка и обновление

После публикации скачайте APK и соответствующий `.sha256` из [официального релиза v1.11.9](https://github.com/Regstar2/tg-ws-proxy-android/releases/tag/v1.11.9). Устанавливайте поверх v1.11.8 с тем же сертификатом подписи **без удаления приложения** — иначе могут быть потеряны настройки, Worker pool и AWG/WARP-профили.

Прежний пакет `com.amurcanov.tgwsproxy` не обновляется поверх `io.github.regstar2.tgwsproxy`. Откат на более низкий `versionCode` поверх установленного приложения не проверен. Встроенное обновление передаёт APK системному установщику после пользовательского подтверждения.

## Известные проблемы

- [#154](https://github.com/Regstar2/tg-ws-proxy-android/issues/154): жалобы на недоступность через конкретных операторов не закрываются без проверки на этих сетях.
- [#155](https://github.com/Regstar2/tg-ws-proxy-android/issues/155): на Realme/Android 16 сообщался отказ переподключения из уведомления с ошибкой занятого порта; этот релиз его не исправляет.
- [#158](https://github.com/Regstar2/tg-ws-proxy-android/issues/158): существующий native WebSocket TLS использует `InsecureSkipVerify=true` и не проверяет цепочку сертификата/hostname upstream. PR #157 не меняет это поведение. Требуется отдельное решение по безопасности перед stable-публикацией.
- Успешный TLS handshake или HTTP 101 не доказывают доставку сообщений или медиа. Подробности: [приёмка #156](../testing/issue-156-cfproxy-sni.md).

## Артефакты
