# v1.11.7 — настраиваемый порядок маршрутов

**Русский** · [English](v1.11.7_EN.md)

## О релизе

v1.11.7 — готовящийся стабильный выпуск TgWsProxy Android. Основное изменение — единый список пяти маршрутов с заданным пользователем порядком резервного подключения для MTProto. Также исправлены отображение фактически выбранного транспорта и показатели уведомления. Это не новый вид сетевого обхода.

Планируемые метаданные: `versionName 1.11.7`, `versionCode 63`, Android 8.0+ (`minSdk 26`), только `arm64-v8a`. Имя приложения и пакет `io.github.regstar2.tgwsproxy` не меняются по сравнению с v1.11.6. **Релиз ещё не опубликован:** финальный подписанный APK, контрольная сумма и проверки на нём не готовы.

## Главное

- Все пять маршрутов на одном экране: менять порядок можно и у выключенных строк, не включая их.
- MTProto пробует только включённые пути в указанном порядке. Один включённый маршрут — без скрытого fallback.
- Уведомление показывает последний подтверждённый исходящий маршрут; после успешного TCP → AWG fallback не должно появляться «Неизвестно» из-за неудачных посторонних подключений.
- Скорость загрузки/отдачи рассчитывается из счётчиков переданных через MTProto данных. Время установления исходящего соединения показывается отдельно от ping.

## Изменения

### Добавлено

- **Настройки → Маршруты:** независимые профили Wi-Fi и мобильной сети, единый список из Cloudflare Proxy, AmneziaWG/WARP, Cloudflare Worker, Direct WebSocket и TCP fallback. Стрелки и перетаскивание перемещают любую строку; выключенные сохраняют свои места. Схема активного fallback отображается отдельно ([#135](https://github.com/Regstar2/tg-ws-proxy-android/issues/135), [PR #137](https://github.com/Regstar2/tg-ws-proxy-android/pull/137)).
- **Метрики MTProto:** живые счётчики байтов передачи в обоих направлениях и длительность успешной установки последнего исходящего соединения.

### Изменено

- Изменения политики маршрутов для новых MTProto-сессий применяются сразу, без кнопки «Применить»; уже установленные сеансы не прерываются намеренно из-за перестановки.
- У **нового или сброшенного** профиля единственный включённый путь — Cloudflare Proxy. Сохранённые профили Wi-Fi/мобильной сети мигрируют с предыдущих настроек с сохранением разрешённых маршрутов и ограничений fallback; если fallback ранее был запрещён, дополнительные пути не включаются.
- Название метрики в раскрытом уведомлении уточнено: **«Установка последнего исходящего соединения»** — это время установления маршрута с учётом fallback, **не RTT и не ping**. Скорость — средняя за интервал, а не мгновенная пропускная способность интерфейса.

### Исправлено

- Фактический маршрут больше не подменяется первым выбранным по приоритету; неудачный локальный handshake и закрытие старой сессии не стирают последний успешный backend.
- В нативном статусе `direct_tcp` отображается как TCP fallback, а успешный fallback `direct_tcp → awg_warp` — как AmneziaWG/WARP.
- Исправлена перестановка направлений загрузки и отдачи при расчёте скорости; в MTProto больше не используются нулевые по умолчанию счётчики SOCKS5.
- Сохранены ограничения частоты публикации уведомления при обновлении скорости, при этом изменение подтверждённого маршрута отображается без ожидания обычного трёхсекундного интервала.

## Установка и обновление

После публикации загрузите подписанный `TgWsProxy-Android-v1.11.7-arm64-v8a.apk` со [страницы v1.11.7](https://github.com/Regstar2/tg-ws-proxy-android/releases/tag/v1.11.7) и сверьте файл с приложенной `.sha256`. Нужны Android 8.0+ и ARM64.

**Переход с v1.11.6:** тот же `applicationId`, поэтому предусмотрена установка поверх приложения с сохранением данных при совпадении сертификата подписи. Перед обновлением сохраните важные параметры конфигурации: сохранение настроек и миграция должны быть проверены на финальном APK. Новая схема маршрутов создаёт упорядоченные профили из старых значений. Если старая политика явно запрещала fallback, она не должна расширяться.

**Установки до v1.11.6:** старый пакет `com.amurcanov.tgwsproxy` отличается и не обновляется поверх `io.github.regstar2.tgwsproxy`. Данные между этими пакетами автоматически не переносятся. Два одновременно запущенных локальных прокси не могут использовать порт `127.0.0.1:1443`.

**Откат:** установка старого APK поверх версии с более высоким `versionCode` и восстановление старой схемы данных без потерь не подтверждены. Не удаляйте приложение для отката без резервной копии конфигурации. Встроенная проверка обновлений открывает GitHub Releases; автоматическая установка APK отсутствует.

## Известные проблемы

- В одном Xiaomi-логе за ~34 секунды наблюдалось **11 801 отклонённое локальное Fake TLS подключение** (`fake tls client hello expected`). Несмотря на успешный TCP → AWG fallback, источник и влияние потока отказов ещё не установлены: [#138](https://github.com/Regstar2/tg-ws-proxy-android/issues/138). Требуется оценка перед публикацией.
- Legacy WebSocket через Cloudflare Worker остаётся экспериментальным: успешный HTTP/WebSocket handshake сам по себе не подтверждает двустороннюю работу Telegram.
- Сетевые ограничения могут делать отдельные маршруты недоступными. Приложение не должно использовать отключённые пути в MTProto-цепочке.
- Доступен только ARM64 APK; 32-битные устройства не поддерживаются этим артефактом.

## Артефакты

После прохождения release gate планируются **ровно два** файла:

- `TgWsProxy-Android-v1.11.7-arm64-v8a.apk` — Android 8.0+, ARM64, подписанный Release APK.
- `TgWsProxy-Android-v1.11.7-arm64-v8a.apk.sha256` — контрольная сумма опубликованного APK.

Размер и SHA-256 появятся только после сборки. Debug APK не является релизным артефактом.
