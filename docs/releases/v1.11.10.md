# TgWsProxy Android v1.11.10 — TLS и Cloudflare WS/80

**Русский** · [English](v1.11.10_EN.md)

## О релизе

v1.11.10 — пока не опубликованный кандидат после v1.11.9. Исправлены переподключение MTProto и копирование Telegram-ссылок, реализованы проверка native TLS-сертификатов, Cloudflare WS/80 и отдельные APK для ARMv7, ARM64 и Universal.

Метаданные: versionName 1.11.10, versionCode 66, Android 8.0+ (minSdk 26), targetSdk 35, applicationId io.github.regstar2.tgwsproxy.

## Главное

- Native WSS/HTTPS проверяет CA chain и hostname upstream; при ошибке сертификата небезопасный fallback запрещён (PR #167).
- MTProto reconnect из уведомления освобождает активный TCP listener (PR #165).
- Кнопка на главном экране копирует полную MTProto или SOCKS5 ссылку (PR #166).
- **CF Proxy без TLS теперь включён по умолчанию**, если ранее выбор не был сохранён. Используется WebSocket через порт 80. При выключении настройки применяется проверяемый WSS/443 (PR #169).
- APK выпускаются для armeabi-v7a, arm64-v8a и Universal, обновлятор учитывает ABI устройства (PR #170).

## Изменения

### Безопасность и сеть

[PR #167](https://github.com/Regstar2/tg-ws-proxy-android/pull/167) добавил проверку сертификатов native WebSocket, Worker Legacy, HTTPS Chunk Relay и TLS/uTLS диагностики. Для Android 14+ учитываются корни Conscrypt APEX CA. Это первая часть [#158](https://github.com/Regstar2/tg-ws-proxy-android/issues/158); финальная проверка Android CA ещё требуется.

[PR #169](https://github.com/Regstar2/tg-ws-proxy-android/pull/169) добавил WS/80. В 1.11.10 он включается по умолчанию только когда ключ `cfproxy_no_tls` отсутствует. Значение false, сохранённое самим пользователем, не меняется; переключение доступно после остановки прокси. **WS/80 не использует TLS, не шифрует участок до Cloudflare и не проверяет подлинность сервера.** MTProto payload шифруется на собственном уровне, но это не заменяет upstream TLS.

### Android и совместимость

[PR #165](https://github.com/Regstar2/tg-ws-proxy-android/pull/165) исправляет ложную ошибку PORT_BUSY при reconnect из уведомления. [PR #166](https://github.com/Regstar2/tg-ws-proxy-android/pull/166) согласует кнопки копирования Telegram-ссылки. [PR #170](https://github.com/Regstar2/tg-ws-proxy-android/pull/170) расширяет набор Android ABI и обновление по ABI.

## Установка и обновление

**После публикации** скачайте подходящий APK и его .sha256 из [официальных GitHub Releases](https://github.com/Regstar2/tg-ws-proxy-android/releases). Установите поверх v1.11.9 с тем же signing certificate, без удаления приложения, иначе потеряются локальные настройки, Worker pool и AWG/WARP-профили. Старый com.amurcanov.tgwsproxy — отдельный пакет без автоматической миграции.

Для локального тестирования доступен `scripts/build-signed-worker-smoke.ps1 -Install` с существующим release-signing.env. Это подписанный релизным ключом **Debug**, а не публичный Release APK.

## Известные ограничения

- Включённый по умолчанию WS/80 работает без TLS и аутентификации сервера. Чтобы вернуть WSS/443, выключите «CF Proxy без TLS».
- Все Android TLS/Worker пути и CA trust roots требуют проверки на финальной подписанной сборке.
- x86 Android Emulator с ARM Native Bridge ранее завершался SIGSEGV/SIGABRT; на физическом Xiaomi ARMv7 работал.
- Проверки одной сети не доказывают доступность у всех операторов. HTTP 101 или транспортный duplex не подтверждают получение Telegram-медиа.
