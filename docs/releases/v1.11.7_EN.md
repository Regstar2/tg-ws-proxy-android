# v1.11.7 — user-controlled route ordering

[Русский](v1.11.7.md) · **English**

## About this release

v1.11.7 is the upcoming TgWsProxy Android stable update. It introduces a unified five-route list with an explicit, user-defined MTProto fallback order, corrects the reported active backend, and repairs notification metrics. It does not add a new censorship-circumvention transport.

Planned metadata: `versionName 1.11.7`, `versionCode 63`, Android 8.0+ (`minSdk 26`), `arm64-v8a` only. The application name and `io.github.regstar2.tgwsproxy` package ID remain unchanged since v1.11.6. **This release has not been published.** The final signed APK, checksum and device acceptance are still pending.

## Highlights

- All five routes share a single reorderable list, including disabled entries.
- MTProto tries only explicitly enabled routes in the configured order; a single enabled route never permits hidden fallback.
- Notifications retain the last confirmed outbound route across unrelated handshake failures. Successful TCP → AWG fallback is shown as AWG.
- Live MTProto upload/download counters drive speed reporting. Last outbound connection setup time is reported separately from network ping.

## Changes

### Added

- **Settings → Routes:** independent Wi-Fi and mobile profiles with Cloudflare Proxy, AmneziaWG/WARP, Cloudflare Worker, Direct WebSocket and TCP fallback in one list. Arrow controls and drag gestures move enabled and disabled rows without toggling them. An ordered fallback summary shows only enabled entries ([#135](https://github.com/Regstar2/tg-ws-proxy-android/issues/135), [PR #137](https://github.com/Regstar2/tg-ws-proxy-android/pull/137)).
- **MTProto metrics:** live byte counters in both directions and elapsed time for the most recent successful outbound connection setup.

### Changed

- Saved MTProto routing changes take effect on new sessions without an Apply button or deliberately terminating established sessions.
- **New or reset** network profiles enable Cloudflare Proxy alone. Existing saved Wi-Fi/mobile policies are migrated without adding formerly forbidden fallback routes; explicitly disabled fallback remains disabled.
- Expanded notification wording now identifies the **last outbound connection setup time**. This includes connection and fallback attempts and is **not RTT or ping**. Speed is an interval average, not an instantaneous interface-rate measurement.

### Fixed

- The displayed backend no longer substitutes the first requested route for the actual confirmed backend; unrelated local handshake errors and stale connection closures do not erase the last successful route.
- Native `direct_tcp` is labeled TCP fallback, and successful `direct_tcp → awg_warp` displays AmneziaWG/WARP.
- Download/upload directions were swapped when calculating displayed speed; MTProto now uses its own real bridge counters instead of defaulting to zero.
- Confirmed route changes may refresh the notification promptly, while routine speed updates remain throttled.

## Installation and updating

Once published, download `TgWsProxy-Android-v1.11.7-arm64-v8a.apk` from the [v1.11.7 release page](https://github.com/Regstar2/tg-ws-proxy-android/releases/tag/v1.11.7) and verify its companion `.sha256` file. Android 8.0+ and ARM64 are required.

**From v1.11.6:** the application ID is unchanged, so the intended upgrade path is an in-place installation with preserved app data, provided the APK has the same signing certificate. Preserve important configuration first: upgrading and data migration must still be validated on the final signed APK. Existing route permissions are converted to the ordered format. A legacy explicit no-fallback policy must not acquire additional enabled routes.

**From pre-v1.11.6:** the older `com.amurcanov.tgwsproxy` package has a different application ID from `io.github.regstar2.tgwsproxy`. The two are separate installations and app data does not transfer automatically. Two local proxy instances cannot bind `127.0.0.1:1443` at the same time.

**Rollback:** installing an older version code in place and safely reversing route-profile migration are not validated. Do not uninstall without preserving important configuration. The built-in update check opens GitHub Releases; there is no automatic APK installation.

## Known issues

- A Xiaomi log recorded **11,801 rejected local Fake TLS handshakes** (`fake tls client hello expected`) in about 34 seconds. TCP → AWG still worked, but the source and performance impact of this rejection storm remain undetermined: [#138](https://github.com/Regstar2/tg-ws-proxy-android/issues/138). It needs triage before publication.
- Flowseal Legacy WebSocket over Cloudflare Worker remains experimental. A successful WebSocket handshake is not evidence of bidirectional Telegram traffic.
- Individual paths may be inaccessible on restricted networks. MTProto must not fall back to disabled paths.
- The published APK target is ARM64 only; it does not support 32-bit-only devices.
