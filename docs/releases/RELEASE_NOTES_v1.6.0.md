# TgWsProxy Android v1.6.0

`v1.6.0` - первый релиз текущей Android-ветки, который собирает вместе не только новые маршруты, но и доводку приложения до более пригодного для ежедневного использования состояния.

## Главное

- Cloudflare Worker как отдельный маршрут.
- Режимы подключения: `Auto`, `Direct + fallback routes`, `Worker first`, `CF first`, `Worker only`, `CF only`, `Direct only`.
- CF-domain pool с ручными, кэшированными upstream и встроенными доменами.
- Более устойчивое обновление CF-доменов: mirror URL, staged diagnostics, cache safety, retry/backoff.
- Adaptive Auto routing с историей маршрутов по сети, last-good route, cooldown и пресетами стратегии.
- Расширенная диагностика с объяснением выбора маршрута и markdown-отчетом для GitHub Issues.
- Действия из foreground notification, метрики скорости/задержки, onboarding, Help/About и релизная полировка интерфейса.

## Маршрутизация и CF-домены

Cloudflare Worker теперь можно использовать как fallback, как приоритетный маршрут или как строгий режим `Worker only`. Режимы `Worker only` и `CF only` намеренно не допускают direct TCP passthrough для Telegram-like трафика.

Порядок выбора CF-доменов:

1. Ручной домен
2. Кэшированный upstream list
3. Встроенный list

Если ручной домен получает `429`, `403`, `5xx`, timeout, TLS или WebSocket failure, он временно уходит в cooldown, а приложение пробует следующий доступный домен или маршрут, если это разрешает выбранный режим.

Обновление CF-доменов теперь best-effort, а не runtime-зависимость. При ошибке, пустом или битом ответе приложение сохраняет прежний cache и при необходимости откатывается к встроенному списку.

## Adaptive Auto routing

`Auto` учитывает профиль сети, недавнее здоровье маршрутов, cooldown, last-good route, latency и накопленную статистику, чтобы выбирать более вероятный рабочий путь.

Доступны пресеты:

- `Balanced`
- `Prefer Direct`
- `Prefer Worker`
- `Prefer CF proxy`
- `Fast failover`

Ручные режимы остаются детерминированными и не переопределяются стратегией Auto.

## Диагностика

В приложении есть точечные проверки Direct, Worker, CF proxy, TCP fallback, CF domains и всего набора маршрутов. Диагностика показывает выбранный маршрут, этап, latency, cooldown, состояние доменов и сводку adaptive routing.

Экспорт может включать markdown-отчет, пригодный для GitHub Issues; домены при необходимости маскируются.

## UI и foreground notification

В `v1.6.0` добавлены:

- onboarding при первом запуске;
- более аккуратная группировка настроек;
- обновленные Help/About со ссылками на репозиторий;
- runtime logs, скрытые по умолчанию за отдельным диалогом;
- действия `Start`, `Stop`, `Reconnect`, `Open` из уведомления;
- опциональные метрики скорости, задержки, маршрута и соединений в приложении и уведомлении;
- режимы уведомления `Normal`, `Compact`, `Minimal`.

Android требует видимое уведомление для foreground service. TgWsProxy может сделать его компактным или минимальным, но не может полностью убрать его во время работы прокси.

## Что не вошло

- `Fake TLS` не реализован.
- `External proxy mode` не реализован.
- `Quick Settings Tile` не входит в `v1.6.0`.

## Известные ограничения

- Для надежной работы через Worker нужен собственный Cloudflare Worker.
- Общие CF-домены могут возвращать `429 Too Many Requests`.
- Direct route все еще может быть нестабилен на части мобильных сетей.
- Adaptive Auto становится полезнее после того, как накопит немного истории подключений.

## Рекомендуемые настройки

- Для большинства пользователей: `Auto` + `Balanced`.
- Если Direct часто ломается: `Worker first`.
- Если есть свой Worker и нужен строгий режим: `Worker only`.
- Если есть надежный CF domain: `CF first`.
- Для тестов маршрута: `Direct only`.

## Что еще вошло в релиз

В релиз также попала миграция launcher/notification assets на versioned `v2` ресурсы и очистка старой иконографики, чтобы презентация приложения и уведомлений выглядела стабильнее на актуальных Android-сборках.
