# TgWsProxy Android v1.11.10 — TLS and Cloudflare WS/80

[Русский](v1.11.10.md) · **English**

## About this release

v1.11.10 is an unpublished candidate following v1.11.9. It fixes MTProto reconnect and Telegram link copying, adds native upstream TLS verification and Cloudflare WS/80, and prepares ARMv7, ARM64 and Universal APKs.

Metadata: versionName 1.11.10, versionCode 66, Android 8.0+ (minSdk 26), targetSdk 35, applicationId io.github.regstar2.tgwsproxy.

## Highlights

- Native WSS/HTTPS validates upstream CA chains and hostnames; certificate errors must not trigger insecure retries (PR #167).
- MTProto notification reconnect releases the running TCP listener first (PR #165).
- The home-screen copy control produces a complete Telegram MTProto or SOCKS5 link (PR #166).
- **CF Proxy without TLS is enabled by default** when no user choice has been saved, using WebSocket port 80. Turning it off selects verified WSS/443 (PR #169).
- Packages cover armeabi-v7a, arm64-v8a and Universal with ABI-aware update selection (PR #170).

## Changes

### Security and connectivity

[PR #167](https://github.com/Regstar2/tg-ws-proxy-android/pull/167) adds certificate verification to native WebSocket, Worker Legacy, HTTPS Chunk Relay and TLS/uTLS diagnostics. Android 14+ Conscrypt APEX CA roots are considered. This is the first part of [#158](https://github.com/Regstar2/tg-ws-proxy-android/issues/158); final Android CA verification remains pending.

[PR #169](https://github.com/Regstar2/tg-ws-proxy-android/pull/169) added WS/80. In v1.11.10 it is the default only if the `cfproxy_no_tls` preference does not exist. Explicitly saved false remains false; the proxy must be stopped before changing transport. **WS/80 does not provide TLS encryption or authenticate the Cloudflare endpoint.** MTProto has its own payload encryption, which does not replace upstream TLS.

### Android and compatibility

[PR #165](https://github.com/Regstar2/tg-ws-proxy-android/pull/165) fixes false PORT_BUSY on notification reconnect. [PR #166](https://github.com/Regstar2/tg-ws-proxy-android/pull/166) aligns Telegram link-copy actions. [PR #170](https://github.com/Regstar2/tg-ws-proxy-android/pull/170) expands the Android ABI and update handling.

## Installation and updating

**After publication**, download a compatible APK and matching .sha256 from [official GitHub Releases](https://github.com/Regstar2/tg-ws-proxy-android/releases). Install over v1.11.9 using the same signer without uninstalling, preserving local settings, Worker pool and AWG/WARP profiles. The legacy com.amurcanov.tgwsproxy package is separate and does not migrate automatically.

For local testing use `scripts/build-signed-worker-smoke.ps1 -Install` with the existing release-signing.env. This is a release-key-signed **Debug** build, not a published Release APK.

## Known limitations

- Default WS/80 lacks encryption and server authentication. Turn off CF Proxy without TLS to restore verified WSS/443.
- Android TLS/Worker routes and CA roots require final signed-APK acceptance.
- ARM Native Bridge previously crashed in x86 Android Emulator; ARMv7 worked on a physical Xiaomi device.
- One carrier test does not prove universal network compatibility; HTTP 101 or transport duplex does not prove Telegram media delivery.
