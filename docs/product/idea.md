# Идея проекта

## Кратко

**TgWsProxy Android** — Android-приложение, которое запускает локальный прокси для Telegram и позволяет маршрутизировать Telegram-соединения через несколько доступных транспортных путей без создания системного VPN-туннеля.

Telegram подключается к локальному frontend приложения через MTProto Proxy или совместимый SOCKS5-режим. Нативный Go runtime затем выбирает разрешённый маршрут к инфраструктуре Telegram.

## Проблема

Доступность конкретных Telegram/Cloudflare-доменов и прямых соединений зависит от сети, провайдера и текущих ограничений. Один фиксированный маршрут может быть доступен в Wi-Fi и недоступен в мобильной сети либо становиться нестабильным со временем.

Проект решает эту проблему на уровне самого Telegram-прокси:

- предоставляет локальный frontend, который можно применить в Telegram;
- поддерживает несколько route kind вместо одного жёстко заданного пути;
- позволяет задавать разные политики для Wi-Fi, мобильной и неизвестной сети;
- предоставляет диагностику фактически выбранного маршрута и причин ошибок;
- сохраняет возможность работать без системного VPN.

## Основной пользовательский сценарий

1. Пользователь устанавливает приложение на Android-устройство.
2. Приложение запускает локальный MTProto Proxy на `127.0.0.1:1443` по умолчанию.
3. Пользователь применяет созданную конфигурацию в Telegram.
4. Runtime направляет соединения Telegram через разрешённые маршруты.
5. При проблемах пользователь проверяет состояние и встроенную диагностику, а не меняет системную сеть для всего устройства.

## Поддерживаемые маршруты

Текущая реализация содержит следующие route kind:

- `cf_proxy_ws` — WebSocket через Cloudflare Proxy domains;
- `direct_ws` — прямой WebSocket к Telegram;
- `cf_worker_ws` — WebSocket через Cloudflare Worker пользователя;
- `tcp_fallback` — прямой TCP к Telegram DC на порту `443`.

Основной проверенный сценарий текущей опубликованной версии `1.10.12` — MTProto Proxy через `cf_proxy_ws`. Доступность каждого внешнего маршрута зависит от сети и внешней инфраструктуры.

## Что проектом не является

TgWsProxy Android:

- не является системным VPN;
- не перенаправляет трафик остальных приложений;
- не обещает доступность любого конкретного внешнего домена;
- не заменяет Telegram-клиент;
- не должен скрывать от пользователя диагностические ограничения или результаты тестов.

## Принципы продукта

- **Локальность:** proxy frontend работает на устройстве пользователя.
- **Явная маршрутизация:** UI и диагностика различают route kind и транспорт.
- **Безопасные значения по умолчанию:** диагностическое логирование и постоянные логи выключены по умолчанию.
- **Наблюдаемость:** ошибки маршрута должны быть диагностируемыми без публикации секретов.
- **Сетевой прагматизм:** устойчивость достигается поддержкой нескольких маршрутов и корректным fallback, а не предположением, что один домен доступен всегда.
- **Проверяемость:** документация должна отделять реализованное и проверенное от запланированного.
