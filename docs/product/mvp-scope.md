# MVP scope

## Назначение

Этот документ фиксирует минимальный продуктовый объём TgWsProxy Android и отделяет обязательное поведение от дополнительных или экспериментальных возможностей.

## Целевой пользователь

Пользователь Android и Telegram, которому нужен локальный Telegram-прокси с несколькими вариантами маршрутизации и диагностикой без включения системного VPN для всего устройства.

## Обязательный scope

### Локальный proxy frontend

- локальный MTProto Proxy;
- совместимый SOCKS5 frontend;
- настраиваемый локальный порт;
- применение MTProto-конфигурации в Telegram через proxy link;
- foreground service и корректный lifecycle локального listener.

### Маршрутизация

Минимально поддерживаются существующие route kind:

- `cf_proxy_ws`;
- `direct_ws`;
- `cf_worker_ws`;
- `tcp_fallback`.

Пользователь может задавать политики отдельно для Wi-Fi, мобильной и неизвестной сети. Недоступность одного внешнего домена не должна трактоваться как гарантия недоступности всех остальных маршрутов.

### Надёжность

- корректный старт/стоп proxy service;
- восстановление listener после сбоя, где это предусмотрено runtime;
- отсутствие зависания UI из-за сетевых операций;
- ограниченный и предсказуемый fallback;
- сохранение пользовательских настроек;
- безопасное поведение при отсутствии сети или недоступности внешней инфраструктуры.

### Диагностика

- отображение настроенного, выбранного и фактически активного маршрута;
- диагностика DNS/TCP/TLS/HTTP/WebSocket там, где применимо;
- видимые причины ошибок и fallback;
- экспорт диагностического отчёта;
- отсутствие автоматической публикации секретов и чувствительных данных.

### Платформа и локализация

- Android `minSdk 26` и выше;
- ABI `arm64-v8a`;
- русский и английский UI;
- пользовательские строки проходят через систему ресурсов Android, а английский используется как fallback.

### Документация и поставка

- README на русском и английском;
- публичные product/architecture/testing/release/version docs;
- сборка APK воспроизводимым документированным способом на поддерживаемом Windows toolchain;
- GitHub Releases как официальный канал опубликованных APK, когда конкретный релиз содержит артефакт.

## В scope v1.10.13

Общая итерация `v1.10.13` включает несколько независимых крупных задач:

1. стабилизация runtime и выборочный sync релевантных изменений `Flowseal/tg-ws-proxy`;
2. выравнивание публичной структуры и документации с `Regstar2/sheduler`;
3. trusted CI, Project sync и release automation;
4. in-app feedback + GitHub Issue Forms;
5. update delivery через GitHub Releases;
6. финальный localization/release/compliance audit.

Эти задачи считаются частью одной версии, но реализуются отдельными Issue/PR, чтобы не смешивать несвязанные изменения в одном diff.

## Вне MVP / не является обязательством

- системный VPN для всего устройства;
- перехват трафика других приложений;
- поддержка всех ABI;
- подтверждённая сборка на Linux/macOS;
- собственная серверная инфраструктура проекта;
- гарантия доступности конкретного Cloudflare/Telegram-домена;
- обязательное использование Cloudflare Worker;
- автоматическая тихая установка APK без участия пользователя;
- публикация приватных governance/AI-файлов (`AGENTS.md`, `.project-rules/`, `docs/ai-prompts/`, `docs/private/`).

## Критерий готовности MVP

MVP считается работоспособным, если на поддерживаемом ARM64 Android-устройстве пользователь может установить APK, запустить локальный proxy, применить его в Telegram, передавать обычные сообщения и медиа через хотя бы один разрешённый маршрут, остановить/перезапустить сервис и получить безопасную диагностику при проблеме.
