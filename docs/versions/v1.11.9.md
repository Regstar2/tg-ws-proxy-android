# v1.11.9 — совместимость Cloudflare Proxy по TLS SNI

## Цель

Подготовить совместимый patch-релиз TgWsProxy Android с исправлением TLS timeout в маршруте Cloudflare Proxy. Важный пользовательский сценарий — подключение Telegram через MTProto frontend и Cloudflare Proxy без изменения остальных маршрутов.

## Входит в версию

- #156 / PR #157: разделение TLS SNI и HTTP WebSocket Host для Cloudflare Proxy.
- Единый контракт для MTProto и SOCKS5: базовый домен в TLS SNI, DC-specific `kwsN.<domain>` в HTTP Host, путь `/apiws`.
- Согласование встроенной RouteProbe диагностики с фактическим TLS/HTTP контрактом.
- Регрессионные Go и Kotlin tests, PowerShell SelfTest и debug-only Android CF-only smoke fixture.
- Документация источника исправления и границ подтверждённой приёмки.

## Не входит в версию

- Гарантия обхода ограничений всех российских операторов и всех сетей.
- Закрытие исходной жалобы #154 без отдельной проверки на затронутых сетях.
- Изменение Cloudflare Worker, Direct WS, AWG/WARP, TCP fallback или общей route policy.
- Изменение package ID, локального порта, ключа подписи, update feed или release workflow.
- Копирование форка malordin целиком.

## Технический контракт

| Поле | Cloudflare Proxy |
| --- | --- |
| TCP destination | upstream Host DC или разрешённый IP |
| TLS SNI | базовый домен зоны |
| HTTP WebSocket Host | `kwsN.<base-domain>` |
| WebSocket path | `/apiws` |
| Frontends | MTProto и SOCKS5 |
| Диагностика | DNS/TCP по upstream Host, TLS по базовому домену, HTTP по исходному Host |

Direct WS и Worker должны сохранять прежние TLS server name и HTTP Host. Пустой явный serverName у общего dialer не меняет существующее поведение.

## Источник исправления

Решение адаптировано из [malordin/tg-ws-proxy-android, commit a98fd27](https://github.com/malordin/tg-ws-proxy-android/commit/a98fd27c384452b8b0e78a4273abf005077aad6b). В исходном форке зафиксирован TLS timeout при SNI `kwsN.<domain>` и успешный WebSocket upgrade при использовании базового домена в SNI. В TgWsProxy перенесено только разделение TLS server name и HTTP Host в существующие пути проекта.

Подробности и границы переноса: [проверка Issue #156](../testing/issue-156-cfproxy-sni.md) и [исходная диагностика форка](https://github.com/malordin/tg-ws-proxy-android/blob/main/docs/fork-sni.md).
