# v1.10.7 - Go MTProto Local Proxy Prototype

## Goal

Add a minimal experimental Go MTProto local listener behind the existing
adapter boundary, without route integration and without claiming full MTProxy
compatibility.

Relevant constraints from docs and upstream:

- MTProto proxy settings require server, port, and secret.
- The selected minimal secret format remains the upstream-confirmed raw
  16-byte / 32-hex `dd` mode.
- Transport/outbound route handling is separate from local listener startup.

## Runtime Behavior

`MTPROTO_EXPERIMENTAL` now attempts to start the Go local-only listener.

If the config is valid and the port is free:

- Go binds `127.0.0.1:<port>`.
- Status is `LISTENING_LOCAL_ONLY`.
- Logs include host, port, status, `OUTBOUND_UNSUPPORTED`, and a short secret
  fingerprint.
- Raw secret is not logged.

If Telegram connects before outbound is implemented:

- the local connection is accepted;
- the connection is closed immediately;
- logs report `OUTBOUND_UNSUPPORTED`.

This is intentionally not a full working MTProto proxy yet.

## Manual Test Plan

1. Default install still starts SOCKS5/WS, not MTProto.
2. Internal MTProto config with valid 32-hex secret starts the local listener.
3. Busy MTProto port reports `FAILED_PORT_IN_USE` / `PORT_BUSY`.
4. Invalid secret reports `FAILED_INVALID_SECRET` / `INVALID_CONFIG`.
5. Stop after MTProto start releases the listener.
6. SOCKS5/WS still starts after MTProto stop.
7. Logs and diagnostic exports do not include the raw MTProto secret.

## Status

MTPROTO_LOCAL_ONLY_LIMITED:

- Local listener exists and is wired through Android/JNA.
- Outbound route integration is not implemented.
- The app must not present this as a fully working Telegram MTProto proxy.

UNSUPPORTED_NO_ROUTE_HOOK:

- Direct/Worker/CF/TCP route integration for MTProto is still unsupported in
  this version.
