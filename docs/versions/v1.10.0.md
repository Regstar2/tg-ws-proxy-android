Prepare the experimental MTProto branch by downloading and auditing current
upstream sources without changing the production runtime.

## Out of Scope

- Production runtime changes.
- UI changes.
- Route selection changes.
- Worker pool changes.
- Gradle/build integration for Rust.
- Vendor/upstream code changes.

## Decision

- Use amurcanov's Rust Android runtime as the Android MTProto candidate.
- Use Flowseal as the behavior reference.
- Keep SOCKS5/WS as the default runtime path.
- Treat MTProto as a separate experimental backend until native build,
  adapter boundaries, and route integration are verified.
