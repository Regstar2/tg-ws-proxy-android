# v1.9.7 — Worker Data Plane Correlation + Media Classification Audit

## Цель версии

Связать Android runtime, Go proxy и Cloudflare Worker по `session_id` для диагностики zero-down сессий (`ws_up_bytes>0`, `ws_down_bytes=0`) и прояснить, когда experimental media DC4 fix реально применён.

## Что входит

- Уникальный `session_id` на каждую `cf_worker_ws`-сессию; query `sid=` в `worker_url`.
- Логи Android/Go с `session_id=` на: SOCKS5 CONNECT, route decision, destination mode, worker_url, Worker WS connected, first_packet_sent_to_worker, bridge close, `worker_session_result`.
- Cloudflare Worker (`scripts/cloudflare-worker/worker.js`): `sid` во всех `console.log` (apiws accepted, ws first packet, tcp connect/open, ws->tcp, tcp->ws, relay close).
- `configured_destination_mode` vs `effective_destination_mode` — не показывать DC4 force, если `flowseal_media_fix_applied=false`.
- Media classification audit: `is_media`, `media_reason`, `telegram_class`, `media_fix_eligible`, `media_fix_skip_reason`.
- Расширенные `destination_mode_stats`: per-profile bytes и session outcomes.

## Что не входит

- Возврат idle WS preconnect (остаётся disabled).
- Изменения основной routing-логики (только observability + sid).

## Ручное тестирование

1. Запустить proxy с Worker; открыть Telegram.
2. В logcat найти `session_id=...` + `worker_url=...sid=...`.
3. В Cloudflare dashboard logs найти тот же `sid`: `ws->tcp packet`, `tcp->ws packet`, `relay close`.
4. Для DC2 core (`is_media=false`, experimental mode on, fix off): `effective_destination_mode=PRESERVE_ORIGINAL_DST`, `media_fix_skip_reason=not_media_or_cdn`.
5. Diagnostics export: destination stats с `up_bytes_total` / `sessions_zero_down`.

## Критерии готовности

- Любая проблемная сессия `ws_up_bytes=524288 ws_down_bytes=0` коррелируется с CF logs по `sid`.
- `flowseal_media_fix_applied=true` только когда fix реально применён.
- Worker pool / first-packet semantics без изменений.
