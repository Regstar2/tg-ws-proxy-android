# v1.10.1 - Proxy Frontend Abstraction

## Goal

Prepare the Android service layer for multiple local proxy frontends while
keeping the existing SOCKS5/WS runtime as the default and only implemented
frontend.

## In Scope

- Add an explicit local frontend type model:
  - `SOCKS5`
  - `MTPROTO_EXPERIMENTAL`
- Persist the selected frontend type with safe migration to `SOCKS5` for
  missing or unknown values.
- Wrap the existing native Go runtime calls in `Socks5LocalProxyFrontend`.
- Add an `MTPROTO_EXPERIMENTAL` placeholder frontend that reports
  `UNSUPPORTED` and does not start a runtime.
- Add unit tests for default, migration, and unsupported MTProto behavior.

## Out of Scope

- Importing MTProto runtime code.
- Rust/NDK/cargo-ndk build integration.
- UI selection for MTProto mode.
- Route backend changes.
- Worker pool changes.
- Diagnostics route truth changes.
- Go runtime changes.

## Architecture Notes

The current production flow remains:

```text
Telegram -> SOCKS5 127.0.0.1:1081 -> ProxyService -> NativeProxy/Go runtime -> route backend
```

`ProxyService` now resolves a `LocalProxyFrontendType` from preferences before
starting. `SOCKS5` maps to `Socks5LocalProxyFrontend`, which calls the same
native methods as before:

- `NativeProxy.setPoolSize(poolSize)`
- `NativeProxy.startProxy("127.0.0.1", port, runtimeConfig, 1)`
- `NativeProxy.getAdaptiveRouteStats()`
- `NativeProxy.stopProxy()`

`MTPROTO_EXPERIMENTAL` maps to an unsupported placeholder. This is intentional:
there is no fake MTProto runtime and no route integration claim in this version.

## Verification

Required checks:

```powershell
.\gradlew.bat test

.\gradlew.bat assembleDebug
```

Additional focused check:

```powershell
.\gradlew.bat testDebugUnitTest --tests "com.amurcanov.tgwsproxy.LocalProxyFrontend*"
```

Observed results:

- Pre-change `.\gradlew.bat assembleDebug`: PASSED.
- `.\gradlew.bat testDebugUnitTest --tests "com.amurcanov.tgwsproxy.LocalProxyFrontend*"`:
  PASSED.
- `.\gradlew.bat test`: FAILED. The new frontend tests passed, but the latest
  full debug unit test run reported 4 failures:
  `NetworkRoutePolicyMapperTest.fromConnectionMode_autoMobileUsesMobileDefault`,
  `NetworkRoutePolicyRepositoryTest.load_mobileDefault_whenEmptyPrefs`,
  `WorkerFailoverResolverTest.deadWorkerWithBackoffSkipped`,
  and `WorkerPoolUiStateMapperTest.maskedUrl_hidesQueryAndSecrets`.
- `.\gradlew.bat lint`: PASSED.
- `.\gradlew.bat assembleDebug`: PASSED.
- `go test ./...` from `native/tgwsproxy`: LIMITED by local environment. With
  default `CGO_ENABLED=0`, the cgo-backed main runtime file is excluded and the
  main package has undefined symbols. With `CGO_ENABLED=1`, the run fails
  because `gcc` is not available in `PATH`. The `tgwsroute` package passed.

## Manual Testing

1. Fresh install or cleared app data starts in SOCKS5 mode.
2. Existing SOCKS5 start/stop/reconnect works with the same port and route
   settings.
3. Route policy behavior is unchanged for direct, worker, cf_proxy, and tcp.
4. If the saved frontend type is manually set to `mtproto_experimental`, the
   service does not start a fake runtime and reports unsupported behavior.
