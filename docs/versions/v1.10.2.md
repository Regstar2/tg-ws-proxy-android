# v1.10.2 - MTProto Config and Secret Model

## Goal

Add MTProto experimental configuration models, validation, storage, and safe
secret handling without starting an MTProto runtime and without changing the
current SOCKS5/WS behavior.

## In Scope

- Add `MtProtoProxyConfig` with safe defaults:
  - host `127.0.0.1`;
  - port `1443`;
  - generated 16-byte / 32-hex secret;
  - `enabled = false`;
  - `experimentalAcknowledged = false`.
- Validate host, port, and upstream-confirmed raw MTProto secret format.
- Generate secrets with platform `SecureRandom`.
- Store/load config via SharedPreferences with corrupted-state fallback to
  safe defaults.
- Mask MTProto secrets in log/report sanitizers and diagnostic report config
  lines.
- Add validation string resources for future UI use.
- Add unit tests for defaults, validation, generation, storage fallback, and
  secret masking.

## Out of Scope

- MTProto native runtime import.
- Rust/NDK/cargo-ndk build integration.
- Route backend changes.
- Worker pool changes.
- Telegram launch/apply UI changes.
- SOCKS5 runtime behavior changes.

## Secret Format

The v1.10.0 upstream audit confirmed the normal `dd` mode uses a raw 16-byte
secret stored as exactly 32 hex characters. Flowseal generates it with
`os.urandom(16).hex()`, and the Android/Rust candidate accepts a 32-character
hex string. This version stores only the raw 32-hex value; `dd`/`ee` link
prefix handling remains out of scope until runtime/link integration.

## Manual Testing

1. Existing SOCKS5 mode starts with the same default port and route settings.
2. Fresh install keeps frontend type `SOCKS5` and MTProto disabled.
3. Saved MTProto config can be loaded after app restart.
4. Corrupted MTProto preferences fall back to disabled defaults.
5. Diagnostic report does not contain the full MTProto secret.

## Status

LIMITED:

- MTProto config and secret storage exist, but no MTProto runtime is started.
- Fake TLS `ee` link-secret handling is not implemented in this version.

UNSUPPORTED:

- `MTPROTO_EXPERIMENTAL` remains unsupported at runtime until a real native
  backend is imported and wired behind the frontend abstraction.
