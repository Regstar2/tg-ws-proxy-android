# v1.11.10 — TLS, WS/80 и поддержка ARMv7

## Цель

Подготовить совместимый релиз после v1.11.9: проверить сертификаты upstream TLS, исправить переподключение и копирование Telegram-ссылок, обеспечить Cloudflare WS/80 и расширить ABI. Публикация остаётся отдельным этапом.

## Изменения

- [PR #165](https://github.com/Regstar2/tg-ws-proxy-android/pull/165): остановка активного MTProto TCP listener перед reconnect из уведомления.
- [PR #166](https://github.com/Regstar2/tg-ws-proxy-android/pull/166): полная MTProto/SOCKS5-ссылка с главного экрана.
- [PR #167](https://github.com/Regstar2/tg-ws-proxy-android/pull/167), первая часть [#158](https://github.com/Regstar2/tg-ws-proxy-android/issues/158): проверка upstream CA chain и hostname в native WSS/HTTPS/uTLS.
- [PR #169](https://github.com/Regstar2/tg-ws-proxy-android/pull/169): Cloudflare Proxy WS/80 без TLS; для 1.11.10 **включён по умолчанию**, если пользователь не сохранял выбор. Явно сохранённый false означает проверяемое WSS/443.
- [PR #170](https://github.com/Regstar2/tg-ws-proxy-android/pull/170), [#162](https://github.com/Regstar2/tg-ws-proxy-android/issues/162): ARMv7, ARM64, Universal APK и ABI-aware updater.

## Не входит

Не добавляются VPN, новые route kind, миграция данных старого Android package и гарантии подключения у всех операторов. Не завершены другие подзадачи #158. Никаких изменений в сертификате подписи и скрытого включения других маршрутов.

## Контракт сборки и сети

- versionName 1.11.10, Release versionCode 66, applicationId io.github.regstar2.tgwsproxy.
- minSdk 26, targetSdk 35; armeabi-v7a, arm64-v8a, Universal (обе ARM ABI).
- Обычный Debug — versionCode 67 и Android debug certificate. `scripts/build-signed-worker-smoke.ps1 -Install` явно использует исходный release certificate, versionCode 66. Этот APK не считается публичным Release.
- При отсутствии сохранённого `cfproxy_no_tls` UI, runtime и RouteProbe должны использовать plaintext WS/80. Явно сохранённый false выбирает WSS/443. Существующая route policy не меняется.
- **WS/80 не шифрует участок до Cloudflare и не аутентифицирует upstream**. MTProto продолжает отдельно шифровать payload. Выключение переключателя восстанавливает проверяемое WSS/443.

## Результаты промежуточных веток

PR #165 и #166 имеют PASS CI и пользовательское Android подтверждение. TLS unit/race regression PR #167 прошла, но реальные Android CA roots/все маршруты не были подтверждены. Отдельный WS/80 APK показал 12/12 корректных проб по Wi-Fi и 7/12 по мобильной сети на Xiaomi Android 14, остальные 5 запросов завершились timeout. В PR #170 native/JNA на ARMv7/ARM64 и Release 1.11.9 прошли; ARM Native Bridge в x86 Android Emulator падал.

Эти результаты не переносятся автоматически на финальный подписанный 1.11.10/66.

## Приёмка до тега

1. Windows CI, Go race, Kotlin unit/lint и ABI audit должны пройти на точном release commit.
2. `scripts/audit-release.ps1 -ExpectedVersion 1.11.10 -ExpectedVersionCode 66` и `scripts/release.ps1 -Version v1.11.10 -PreflightOnly` должны завершиться успешно.
3. Проверить три APK с исходным release key: packageName, versionCode, ELF/JNA, signer и SHA-256.
4. На Android проверить Conscrypt CA roots, CF WSS/443 DC2/DC4, Direct WS, Worker Legacy WS, HTTPS Chunk Relay и controlled invalid certificate fixtures.
5. Проверить новый default WS/80, сохранённый false/WSS/443, переключение при остановленном сервисе, Quick Settings, notification reconnect, ссылки Telegram, Wi-Fi/mobile и media.
6. Подтвердить in-place обновление опубликованной v1.11.9 без удаления пользовательских данных.
7. Только после решения GO создавать аннотированный tag v1.11.10 и запускать exact-tag CI.
