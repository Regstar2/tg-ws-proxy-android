# v1.9.2 — Worker Failover

## Goal

When the selected Worker is unavailable, try other enabled Workers for new Worker WebSocket connection attempts without changing the user's `selectedWorkerId` or migrating active connections.

## In scope

- `WorkerFailoverCandidate`, `WorkerFailoverResult`, `WorkerFailoverReason`, `WorkerConnectionAttemptState`
- `WorkerFailoverResolver` (Kotlin) — candidate ordering, backoff skip, max attempts
- `WorkerFailoverConfigBuilder` — builds runtime tokens for Go
- Go `tryWorkerFailoverConnect` in Worker WebSocket route (`cfWorkerFallback`)
- Runtime Route Truth: selected vs runtime worker, last success/failure, failover reason/attempts
- `WorkerRuntimeFailureRecorder` — updates worker health state on runtime success/failure
- UI: Route status block, Worker Pool summary, Diagnostics failover section
- Diagnostic report `[Worker Failover]` section
- Persistent logs / logcat for failover lifecycle
- Unit tests (Kotlin resolver + Go candidate parsing)
- Version `1.9.2` (`versionCode` 43)

## Out of scope

- Round-robin, lowest-latency, weighted balancing, selection strategy UI
- Worker groups, import/export, advanced analytics
- Changing `selectedWorkerId` from runtime failover
- Moving an already-open WebSocket to another worker

## Constraints

- Failover only for new connection attempts within the same dial sequence
- Max attempts capped (`DEFAULT_MAX_WORKER_FAILOVER_ATTEMPTS = 3`)
- DEAD workers with active backoff skipped (from v1.9.1 policy)
- Worker route exhaustion returns typed error; Cloudflare/Direct fallback unchanged
- No raw secrets in UI/logs/report

## Manual testing

Critical scenario 1: selected worker dead, second worker works → runtime worker switches, selected unchanged.

Critical scenario 2: all workers fail → limited attempts, `ALL_WORKERS_FAILED`, CF fallback if policy allows.

Verify Diagnostic Report failover section and masked URLs.

## Risks

- Failover state in Go resets on proxy restart; Android enriches selected worker from pool
- Worker pool idle cache is per-domain; failover opens new connections per candidate

## Done criteria

Build + tests pass; failover tries next enabled worker; selectedWorkerId unchanged; UI/report/logs show failover state; no round-robin/balancing.
