# v1.9.0 — Worker Pool Foundation

## Goal

Store multiple Worker endpoints, expose them in settings, and route Worker WebSocket connections through a manually selected Worker. No automatic balancing or health-based selection in this release.

## In scope

- `WorkerEndpoint`, `WorkerPoolConfig`, `WorkerHealthState`
- `WorkerPoolRepository` with SharedPreferences persistence
- Safe migration from legacy single `worker_domain` to first pool entry
- Worker Pool settings UI (list, add, edit, delete, enable/disable, select)
- Worker WebSocket route uses selected Worker when pool is enabled
- Runtime route truth and diagnostic report show current Worker (masked URL)
- Route probe `WORKER_WEBSOCKET` checks selected Worker only
- Unit tests for repository, resolver, validator, URL masking
- Version `1.9.0` (`versionCode` 41)

## Out of scope

- Worker health check, failover, round-robin, lowest-latency, weighted balancing
- Probe/check all workers, worker groups, import/export
- MTProto Proxy Mode, Network Profiles UI
- Automatic route changes from diagnostics

## Constraints

- Pool does not switch Worker inside an active connection
- Disabled workers are excluded from new Worker route connections
- Legacy `worker_domain` remains for backward compatibility when pool is off
- No raw secrets in UI, logs, or diagnostic report

## Manual testing

1. Upgrade from v1.8.4 with one legacy Worker domain → open Worker Pool → verify `Worker 1` migrated.
2. Restart app twice → no duplicate workers.
3. Enable Worker Pool, add Worker 2, select it, start Worker WebSocket route → Runtime Route Truth shows Worker 2.
4. Generate diagnostic report → `[Worker Pool]` section with masked URLs.
5. Disable selected worker → selection moves to next enabled worker or clears.
6. Confirm no automatic failover between workers on connection error.

## Risks

- Pool disabled by default after migration; user must enable pool to use multi-worker routing.
- Go runtime still exports `current_worker_domain` only; Android enriches Worker name/state for UI.

## Done criteria

Build and unit tests pass; pool CRUD works; selected Worker used for new Worker WS connections; report and UI mask URLs; no balancing/failover logic added.
