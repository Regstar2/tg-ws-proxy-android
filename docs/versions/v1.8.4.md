# v1.8.4 — Diagnostic Report + Persistent Logs

## Goal

Give users a one-tap local diagnostic report (runtime route, probe results, recent logs) and optional persistent file logging with rotation, clear, and export.

## In scope

- `DiagnosticReportGenerator`, `DiagnosticReportSanitizer`, `DiagnosticReportExporter`
- Copy / share report on Diagnostics screen
- Report sections: app, device, network, runtime route, probes, config, route events, recent logs, persistent logs state
- Persistent logs: existing store enhanced (1 MB rotation, 3 archived files), settings unchanged in Settings → App
- Sanitization for tokens, secrets, Authorization, URL query params
- Unit tests for sanitizer, generator, log tail read
- Version `1.8.4` (`versionCode` 40)

## Out of scope

- Auto route switching from probe/report
- Remote telemetry / auto-send
- Worker Pool, Network Profiles UI, complex log viewer
- Save report via SAF (share via FileProvider cache file is enough for v1.8.4)

## Constraints

- Read-only: report generation must not change active route or proxy service
- App-specific storage only; no extra storage permissions
- UI thread must not block on large file reads

## Files

- `diagnostics/DiagnosticReport*.kt`
- `PersistentLogLimits.kt`, `PersistentLogStore.kt` (size rotation)
- `AppLogSanitizer.kt` (URL query + Bearer)
- `DiagnosticsScreen.kt`, `DiagnosticsViewModel.kt`
- `strings.xml` (EN/RU)

## Manual testing

1. Open Diagnostics → Copy report → verify clipboard has masked report with runtime route and probes.
2. Share report → verify share sheet and `.txt` attachment.
3. Enable persistent logs → restart app → verify log file exists; export/clear from Settings.
4. Confirm active route unchanged after report copy/share.

## Risks

- Large in-memory log buffer still capped in report (`DEFAULT_REPORT_LOG_LINES = 200`).
- Numbered rotation coexists with date-based archive names.

## Done criteria

Build passes; report copy/share works; persistent logs default off; sanitization tests pass.
