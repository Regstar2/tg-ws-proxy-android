# v1.10.8 - MTProto Telegram Link UI

## Goal

Add UI/UX for the experimental MTProto frontend without route integration:
frontend mode selection, local MTProto config display, runtime status, and
Telegram proxy link copy/share actions.

## Source Checks

Official Telegram docs checked:

- `https://core.telegram.org/api/links`
- `https://core.telegram.org/proxy`
- `https://core.telegram.org/mtproto/mtproto-transports`
- `https://core.telegram.org/tdlib/docs/classtd_1_1td__api_1_1proxy_type_mtproto.html`

Confirmed:

- MTProxy deep links use `t.me/proxy?server=<server>&port=<port>&secret=<secret>`.
- `tg://proxy?server=<server>&port=<port>&secret=<secret>` is the URI form.
- MTProto proxy secrets are hexadecimal strings.
- A 17-byte secret with leading `dd` selects the padded intermediate transport.

## In Scope

- Add a frontend mode switch in Connection settings:
  - `SOCKS5 / WebSocket` as stable default.
  - `MTProto Proxy` as experimental.
- Keep the switch separate from route policy settings.
- Show MTProto local host, local port, masked secret status, runtime status, and
  explicit experimental warning.
- Add regenerate secret, copy Telegram proxy link, and share Telegram proxy link
  actions.
- Generate links from saved raw 32-hex secrets as `dd<secret>` link secrets.
- Allow the main Apply in Telegram action to use `tg://proxy` when MTProto is
  selected.
- Keep SOCKS5/WS startup behavior unchanged.

## Out of Scope

- MTProto route integration.
- Worker pool changes.
- Go runtime behavior changes.
- Native/Rust build changes.
- Claiming end-to-end MTProxy readiness.

## Runtime Status UI

Allowed UI statuses:

- `SOCKS5_WS_STABLE`
- `MTPROTO_DISABLED`
- `MTPROTO_EXPERIMENTAL`
- `MTPROTO_LOCAL_LISTENING`
- `MTPROTO_LOCAL_ONLY_LIMITED`
- `MTPROTO_FAILED`

The v1.10.7 Go listener maps to `MTPROTO_LOCAL_ONLY_LIMITED`, not a ready state,
because outbound route integration is still unsupported.
