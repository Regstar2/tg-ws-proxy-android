# v1.8.1 — Runtime Route Truth

## Goal

Eliminate false route display: configured user mode must not be shown as the active route when fallback is in use.

## In scope

- `RouteRuntimeState` in Go (`route_runtime_state.go`) updated at real routing events.
- Extended `GetProxyStatus` fields: `configured_mode`, `selected_route`, `last_success_route`, `last_failed_route`, `fallback_reason`, `network_type`, etc.
- Structured logs: `Route selected`, `Route connect started/succeeded/failed`, `Fallback activated`, `Active route changed`, `Connection closed`.
- Android: `RouteRuntimeState`, metrics card route status block, EN/RU strings.
- Version bump to `1.8.1` (`versionCode` 37).

## Out of scope

- Worker Pool, multi-worker health, round-robin, large diagnostics screen, MTProto mode, network profiles UI, persistent log file, export report.

## Changed modules

- `native/tgwsproxy/route_runtime_state.go`, `proxy_status_bridge.go`, `routing.go`, `adaptive_bridge.go`, `tg-ws-proxy.go`
- `app/.../RouteRuntimeState.kt`, `RouteRuntimeStatusBlock.kt`, `ProxyRuntimeMetrics.kt`, `ProxyConnectionMetricsCard.kt`
- `app/src/main/res/values/strings.xml`, `values-ru/strings.xml`

## Manual testing

Worker-first with a failed Worker must still show the configured Worker-first mode, the selected Worker WebSocket route, the active Cloudflare Proxy fallback, and the Worker failure reason.

## Done criteria

1. Build succeeds.
2. UI does not equate configured mode with active route.
3. Logs reconstruct route selection chain.
4. Unknown routes shown honestly.
5. No Worker Pool or future-scope features added.

## Risks

- Multiple concurrent Telegram connections may use different routes; UI shows last `noteActiveRoute` (same as pre-1.8.1 active route semantics).
- Native rebuild required after Go changes.
