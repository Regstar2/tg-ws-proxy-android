# v1.9.1 — Worker Health Check

## Goal

Add diagnostic health checks for each Worker endpoint in the pool. Show availability, latency, and failure state to the user without changing routing, selected worker, or active connections.

## In scope

- `WorkerHealthCheckResult`, `WorkerHealthCheckStatus`, `WorkerHealthCheckStep`, `WorkerHealthErrorCode`
- `WorkerHealthCheckRunner` (DNS / TCP / TLS / WebSocket handshake; no Telegram payload)
- `WorkerHealthRepository` with `checkWorker`, `checkAllEnabledWorkers`, last results cache
- `WorkerHealthStateResolver` (1 failure → DEGRADED, 3 consecutive → DEAD, success resets)
- `WorkerHealthBackoffPolicy` (prepared for future automatic checks; manual checks always allowed)
- Worker Pool UI: Check worker, Check all workers, state/latency/last checked/error
- Diagnostics screen: Worker Pool health summary + Check all workers
- Diagnostic report: expanded `[Worker Pool]` section with per-worker health fields
- Persistent logs via `AppLogger` / logcat for health check lifecycle
- URL masking via existing `WorkerUrlSanitizer`
- Unit tests for state transitions, backoff, persistence isolation
- Version `1.9.1` (`versionCode` 42)

## Out of scope

- Worker failover, round-robin, lowest-latency, weighted balancing
- Automatic route/selected-worker changes on DEAD state
- Worker groups, import/export, advanced analytics
- Background schedulers (WorkManager / AlarmManager) for health checks

## Constraints

- Health check must not change `selectedWorkerId`, `activeRoute`, or restart proxy
- Disabled workers are SKIPPED on check-all (unless explicitly checked individually)
- DEAD is diagnostic state only — no automatic failover (v1.9.2)
- No raw secrets in UI, logs, or reports

## Manual testing

1. Add 3 workers: one working, one unreachable, one disabled.
2. Tap **Check all workers** → working = HEALTHY, unreachable = DEGRADED/DEAD, disabled = SKIPPED.
3. Confirm `selectedWorkerId` and Runtime Route Truth unchanged.
4. Generate diagnostic report → worker states, latency, failureCount; no raw URLs with secrets.
5. Disabled worker: individual check shows SKIPPED; not probed on check-all network steps.
6. Successful re-check resets `failureCount` and sets HEALTHY.

## Risks

- Health check opens real network connections to Worker hosts (same as route probe).
- Unreachable workers may show DEGRADED after first failure even if route probe to selected worker still works.

## Done criteria

Build and unit tests pass; UI shows health state; report/logs mask URLs; no routing side effects; no failover logic.
